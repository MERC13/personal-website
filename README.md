# personal-website

Source for [merc13.github.io/personal-website](https://merc13.github.io/personal-website/).

No frameworks, no build step, no dependencies. Static files served straight from
the repo root by GitHub Pages. Without JavaScript every section still reads, with
static numbers in place of the interactive demos.

```
index.html                   all content: experience, education, projects, JSON-LD
404.html                     own doctype and styles; links use /personal-website/
favicon.svg, robots.txt, sitemap.xml
assets/style.css             tokens (dark and light), layout, the shared .demo panel, print
assets/script.js             theme toggle, copy buttons, hero voxel field, and every demo
assets/data.js               generated by tools/build_data.py; do not edit by hand
assets/jonah-cha-resume.pdf  the one-page résumé
assets/fonts/                STIX Two Text and Inter, subset (OFL, licence included)
assets/img/                  og.png (social preview), gan-cifar10-epoch10.jpg
tools/build_data.py          writes assets/data.js from tools/data/
tools/data/                  cae_forest.json (failure-detection-WM), steer_prompts.json
                             (openpi steering-rl), penguins.csv (Palmer Penguins, CC0)
```

## Local preview

GitHub Pages serves the site under `/personal-website/`, so serve the parent
folder to make the subpath real:

```sh
cd ..
python -m http.server 8000
```

Then open <http://localhost:8000/personal-website/>.

## Editing

- Content is ordinary markup in `index.html`. Each role and project is one entry;
  a demo is a `<figure class="demo" data-demo="NAME">` that `script.js` fills in.
- The forest plot, the steering grid and the K-means demo read `assets/data.js`.
  Change the files in `tools/data/`, then run `python -I tools/build_data.py`.
- The UCSF charts' numbers live in `script.js` (the "brain decoding results"
  block), copied from the project's results write-up.
- Bump the `?v=` query on the stylesheet and scripts in `index.html` when they
  change, so returning visitors don't get a cached copy.

Rules worth keeping:

1. **Every project entry links to something**: a repo, a live site, or a paper.
2. **Check the links before deploying.**
3. **Demos are drawn from real results.** Anything illustrative (the Uplevel
   pipeline, the lecture replay) says so on the panel. Nothing from client-owned
   or NDA work goes on the page.
4. **The résumé PDF and the site never show a phone number.**
